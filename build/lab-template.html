Switch-level sweeps, run here rather than reported from somewhere else. The solver is R2 — the same fixed-point algorithm src/device.js defines, over the packed form, in WebAssembly — and the module is emitted by JavaScript on this page at load time. No committed binary, no base64 blob, no toolchain: the emitter ships and the page calls it.

The pass count is not a second solver. solvePasses is solve's own body with one node replaced — the return 1 that fires when a pass changes nothing becomes return iter + 1 — so what counts the passes is the loop that takes them. Every other function in the module is src/solver-wasm.js's, unaltered, and a sweep that does not settle inside the cap reports the bound rather than a half-settled state.

1 — the network, and what it costs

designswitchesmid-rail tapsrails

Two columns, and they are never added together. A mid-rail tap is a switch that touches vmid, and this device model gives vmid away free — so every switch of ternary's margin over the binary row is borrowed from the one column the model prices at zero. Folding the taps into the switch count, or leaving them out of the table, would each turn a comparison into an assertion.

The oracle is T.add out of src/ternary.js, and the carry-out is what that wrap threw away. "Did not settle" is counted apart from "got it wrong": a pair that ran out of passes has no answer to disagree with, and conflating the two has produced a false verdict in this repository before.

A pass is one sweep of the whole network: conduction once per device, then rails × 2 reachability walks, then every undriven node re-derived. One bucket means the settling time does not depend on the data; more than one means it does.
