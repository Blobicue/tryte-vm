Balanced ternary · emulator

Tryte VM

A working computer that counts in three states instead of two. A digit here is not a light switch but a balance scale: it tips left, sits level, or tips right — −1, 0, +1. Weights go on either pan, so negative numbers stop being a special case.

Everything below runs the actual emulator source, inlined from the same files the 582-test suite checks — including 42 that drive these very controls headlessly. Nothing here is a mock-up.

01 — the number

One tryte, six scales

Six trits make a tryte: 36 = 729 values, running −364 to +364. Type a number and watch the scales settle. Then press Negate — every scale simply tips the other way. That is the whole operation; there is no sign digit to flip and no two's complement.

02 — the machine

Three registers, 729 cells

Memory is addressed −364 … +364, so address 0 is the centre of memory rather than one end. Pick a program, give it inputs, and step through it. multiply is the one to watch: the machine has no multiply instruction, so it extracts one trit at a time using v − 3 × (v ≫ 1) — which only works because shifting right rounds to nearest instead of truncating.

Switch Execution to Emulated and the same program runs on a tryte VM written in this assembly, itself running on this machine. ×2 and ×3 stack more of them. Same source, same inputs, same output at every level — for about 27× the instructions per level, so roughly 19,000× three deep. Only threeway is small enough to go that far; the others will tell you so.

      03 — the reconfigurable unit
      
A control word that is the circuit

      
Each of the six switches sets what that slice of the unit does — negate, min, or max —
        so one control tryte names one of 729 distinct six-slice circuits. Min is the AND analog and max is
        the OR analog; on three-state data this is a real three-way choice per position rather than an
        opcode picking between two.

      04 — instruction set
      
Twenty-two instructions

      
BR3 is the one with no binary equivalent: it inspects the accumulator once
        and lands on one of three addresses. No flags register, no chain of compares.

      
The last three — LOADX, STOREX,
        JMPX — were added only when the machine was asked to emulate itself.
        An interpreter must read memory at an address it computes, and every other instruction here
        bakes its address in when the program is assembled. Nineteen instructions and a full test suite said
        nothing about the gap; trying to bootstrap found it in the first five minutes.

Where this came from. A Google AI Mode conversation designed a "tryte ALU"
      and offered three separate times to implement balanced ternary arithmetic, then never did — every artifact
      it produced was binary logic in ternary vocabulary, down to a Verilog module encoding the trit as two binary
      wires. This is the part it kept promising.

    
Prior art. Setun, built in 1958 at Moscow State University under Sergei
      Sobolev and Nikolay Brusentsov, was the first modern ternary computer and used this same balanced system.
      Around 50 were built between 1959 and 1965 from ferrite cores and diodes.
